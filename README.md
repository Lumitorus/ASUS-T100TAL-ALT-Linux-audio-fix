# Исправление встроенного звука ASUS Transformer T100TAL в ALT Linux

Воспроизводимая инструкция и самостоятельный POSIX sh-скрипт по результатам диагностики конкретного ноутбука. Дата подтверждения результата: **11 октября 2026 года**.

**Результат:** локальный звук работал более 50 минут без прежнего писка и исчезновения. Затем владелец самостоятельно перезагрузил ноутбук и подтвердил, что проблем со звуком не обнаружил. Встроенный звук на этом экземпляре считаем исправленным.

Инструкция рассчитана прежде всего на **ASUS T100TAL, ALT Linux 11 p11, PipeWire и WirePlumber 0.5**. Другие модели T100 могут иметь иной кодек, прошивку и маршрутизацию. Приведённые параметры следует переносить на них после проверки оборудования, а не только по похожему названию корпуса.


## Быстрый старт

В репозитории есть [restore-t100-audio.sh](restore-t100-audio.sh). Он содержит оба конфигурационных файла внутри себя: отдельные архивы, логин автора и каталоги из его ноутбука не нужны.

На **T100TAL с ALT Linux, SOF/RT5640 и WirePlumber 0.5** откройте терминал своего графического пользователя:

```sh
git clone https://github.com/Lumitorus/ASUS-T100TAL-ALT-Linux-audio-fix.git
cd ASUS-T100TAL-ALT-Linux-audio-fix
sh restore-t100-audio.sh --check
sh restore-t100-audio.sh --install
```

Скрипт запросит sudo, сохранит текущие настройки и покажет путь резервной копии. Он перезапустит аудиослужбы, кратко прервав звук, но **сам не перезагрузит ноутбук**. Сохраните документы и выполните:

```sh
sudo systemctl reboot
```

Если Git не установлен, скачайте ZIP через GitHub → **Code → Download ZIP**, распакуйте и запустите скрипт из распакованной папки. Не передавайте сетевой ответ напрямую в `sudo sh`.

Ограничения и все режимы описаны в [разделе 8](#8-восстановление-готовым-sh-скриптом).

## 1. Рабочая конфигурация

| Компонент | Проверенное состояние |
|---|---|
| Ноутбук | ASUS Transformer T100TAL |
| Процессор | Intel Atom Z3735D, Bay Trail |
| Память | Около 2 ГБ |
| Система | ALT Linux 11, ветка p11 |
| Рабочий стол | Xfce |
| Ядро | `6.12.61-6.12-alt1` |
| Звуковой кодек | Семейство RT5640; ACPI-устройство `10EC5642` |
| Встроенная ALSA-карта | `sof-bytcht rt5640` |
| Драйвер DSP | SOF, штатный автоматический выбор |
| Прошивка SOF | 2.2.0, `intel/sof/sof-byt.ri` |
| Topology | `intel/sof-tplg/sof-byt-rt5640.tplg` |
| PipeWire | 1.4.7 |
| WirePlumber | 0.5.11.1 |
| Параметр SOF | `sof_debug=1` |
| Формат встроенного аудиотракта | `S16LE` |
| Доступ PipeWire к ALSA | mmap отключён правилом WirePlumber |

HDMI-аудио — отдельная карта. Во время диагностики HDMI имело номер 0, встроенная карта — 1. После обновлений или подключения USB-устройств номера могут поменяться. Для постоянной настройки мы использовали имя узла, а не номер карты.

## 2. Как проявлялась проблема

При первоначальной конфигурации звук сначала работал, а спустя несколько минут мог:

- превратиться в постоянный писк или искажения;
- полностью исчезнуть, хотя плеер продолжал воспроизведение;
- временно вернуться после перезапуска аудиослужб;
- снова пропасть под обычной работой или нагрузкой.

Внешний аудиодекодер работал лучше. Это было полезным наблюдением, но само по себе не доказывало поломку встроенного кодека.

Во время некоторых сбоев ALSA показывала `RUNNING`, её аппаратный указатель продолжал двигаться, а PipeWire показывал ноль ошибок. Поэтому движущийся прогресс-бар, наличие карты и отсутствие сообщений в журнале ещё не означали, что динамики действительно получают нормальный звук.

Проблема воспроизвелась и при непрерывном прямом ALSA-тесте без PipeWire и без передачи с телефона. Следовательно, ранний сбой нельзя было объяснить только Bluetooth или настройками конкретного браузера.

## 3. Что именно помогло

В итоговой конфигурации сохранены два изменения.

### 3.1. Параметр SOF

Файл `/etc/modprobe.d/codex-t100-sof.conf`:

```conf
# Bay Trail SOF: enable DMA trace
options snd_sof sof_debug=1
```

Для похожего писка на Bay Trail / Cherry Trail разработчики SOF описывали включение DMA trace как обходной путь. Это основание для проверки параметра, а не доказательство, что он исправляет любой ноутбук: [SOF issue #4329](https://github.com/thesofproject/sof/issues/4329).

### 3.2. Правило WirePlumber

Файл пользователя `~/.config/wireplumber/wireplumber.conf.d/51-codex-t100-alsa.conf`:

```conf
monitor.alsa.rules = [
  {
    matches = [
      { node.name = "~alsa_.*platform-bytcr_rt5640.*" }
    ]
    actions = {
      update-props = {
        audio.format = "S16LE"
        api.alsa.disable-mmap = true
      }
    }
  }
]
```

Правило применяется к узлам встроенного RT5640, включая вход и выход, если их имена подходят под шаблон. Оно не назначает эти свойства всем Bluetooth- или HDMI-устройствам.

`S16LE` задаёт 16-битный знаковый формат little-endian. Отключение mmap меняет способ доступа аудиосервера к ALSA. Во время проверки фактические параметры встроенного выхода были `RW_INTERLEAVED` и `S16_LE`.

**Что мы можем утверждать:** текущая комбинация прошла длительное локальное воспроизведение и пользовательскую проверку после перезагрузки.

**Что осталось неизвестным:** вклад каждого параметра отдельно. Ранее один `sof_debug=1` не обеспечил устойчивость; S16LE без mmap с выключенным SOF debug тоже не обеспечил устойчивость. Поэтому в инструкции фиксируется проверенная комбинация, а не универсальная причина сбоя.

Дополнительно на последнем этапе на 20 минут запускался `sof-logger` для непрерывного чтения trace. После его остановки локальное воспроизведение продолжало работать; затем звук сохранился после новой перезагрузки. Постоянно запускать сборщик журнала для этого исправления не требуется.

## 4. Проверка системы перед изменениями

Команды этого раздела выполняются в терминале пользователя, вошедшего в графический сеанс. Они только читают состояние.

```sh
cat /sys/class/dmi/id/product_name
uname -r
cat /etc/os-release
cat /proc/asound/cards
aplay -l
pipewire --version
wireplumber --version
wpctl status
```

На проверенном ноутбуке модель — `T100TAL`, карта — `sof-bytcht rt5640`. Если карта отсутствует, сначала разбирайте её регистрацию и загрузку прошивки: правило WirePlumber не создаёт отсутствующее устройство ядра.

Проверить сообщения загрузки:

```sh
sudo journalctl -k -b --no-pager |
  grep -Ei 'sof|rt5640|5642|firmware|topology|sst|oops'
```

Проверить существующие настройки:

```sh
sudo grep -RnsE 'sof_debug|dsp_driver|quirk=' /etc/modprobe.d
grep -RnsE 'disable-mmap|audio.format|period-size|headroom' \
  "$HOME/.config/wireplumber" /etc/wireplumber 2>/dev/null
```

Наличие файла с другим именем не означает, что он не действует. Конфликтующие параметры могут находиться в любом `.conf` соответствующего каталога.

Конфигурация ниже использует синтаксис WirePlumber 0.5. Если установлена другая основная версия, сначала проверьте её формат конфигурации. Правила и механизм совпадения узлов описаны в [официальной документации WirePlumber](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/alsa.html).

## 5. Установка исправления вручную

Эти шаги предназначены для аналогичной установки ALT с уже работающей регистрацией карты SOF/RT5640. Для установки на совместимом ноутбуке можно использовать опубликованный самостоятельный скрипт из раздела 8.

### Шаг 1. Сохранить исходные настройки

```sh
audio_backup="$HOME/t100-audio-before-fix-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$audio_backup"
sudo cp -a /etc/modprobe.d "$audio_backup/modprobe.d"
if [ -d "$HOME/.config/wireplumber" ]; then
  cp -a "$HOME/.config/wireplumber" "$audio_backup/wireplumber"
fi
uname -r > "$audio_backup/kernel.txt"
cat /proc/asound/cards > "$audio_backup/cards.txt"
printf 'Backup: %s\n' "$audio_backup"
```

Корневая копия modprobe может содержать файлы, доступные только root. Это нормально; восстанавливать их следует через sudo.

### Шаг 2. Проверить отсутствие экспериментальных переопределений

В нашей диагностике были отменены отдельные файлы, принудительно включавшие SST и MCLK 25 МГц. Итоговая система не содержит активных `codex-t100-sst.conf` и `codex-t100-clock.conf`.

Если такие файлы сохранились у вас, прочитайте их и переместите в резервный каталог перед применением рабочей схемы. Не удаляйте весь `/etc/modprobe.d` и не отключайте незнакомые настройки других устройств.

Штатный автоматический выбор драйвера на проверенной системе загружает SOF. Отдельное принудительное значение `dsp_driver` в рабочей конфигурации не понадобилось.

### Шаг 3. Добавить параметр SOF

```sh
sudo tee /etc/modprobe.d/codex-t100-sof.conf >/dev/null <<'EOF'
# Bay Trail SOF: enable DMA trace
options snd_sof sof_debug=1
EOF
```

Файл предназначен для последующей загрузки модуля. Не пытайтесь применять его принудительной выгрузкой аудиодрайверов в работающем сеансе.

### Шаг 4. Добавить пользовательское правило WirePlumber

Команду выполнять от обычного пользователя, который слушает звук. Не запускайте весь блок через `sudo sh`: иначе `$HOME` может указывать на домашний каталог root.

```sh
mkdir -p "$HOME/.config/wireplumber/wireplumber.conf.d"
cat > "$HOME/.config/wireplumber/wireplumber.conf.d/51-codex-t100-alsa.conf" <<'EOF'
monitor.alsa.rules = [
  {
    matches = [
      { node.name = "~alsa_.*platform-bytcr_rt5640.*" }
    ]
    actions = {
      update-props = {
        audio.format = "S16LE"
        api.alsa.disable-mmap = true
      }
    }
  }
]
EOF
```

### Шаг 5. Перезагрузить

Сохранить открытые документы и выполнить:

```sh
sudo systemctl reboot
```

На проверенной установке отдельное изменение GRUB или пересборка initramfs для этого параметра не требовались: после обычной загрузки значение применялось. Если у другой установки параметр не применился, проверяйте, откуда загружается модуль и нет ли настройки внутри initramfs; не добавляйте случайные загрузочные параметры.

## 6. Проверка результата

### 6.1. Параметр модуля и службы

```sh
cat /sys/module/snd_sof/parameters/sof_debug
cat /proc/asound/cards
systemctl --user is-active pipewire pipewire-pulse wireplumber
wpctl status
```

Ожидается `1` для SOF debug, зарегистрированная встроенная карта и активные аудиослужбы. Также проверьте выбранный выход и громкость в настройках звука.

### 6.2. Проверка обоих каналов

Если тестовые файлы присутствуют:

```sh
pw-play /usr/share/sounds/alsa/Front_Left.wav
pw-play /usr/share/sounds/alsa/Front_Right.wav
```

Команда `pw-play` входит в инструменты PipeWire; на проверенном ноутбуке она была доступна. Если файлов нет, используйте известную локальную стереозапись, а не считайте отсутствие файла неисправностью карты.

Короткие записи слов содержат начало, конец и паузы. По ним нельзя уверенно оценивать непрерывность длинного потока.

### 6.3. Фактический формат ALSA

Пока играет музыка, найдите номер встроенной карты в `/proc/asound/cards`. Для карты 1:

```sh
cat /proc/asound/card1/pcm0p/sub0/hw_params
cat /proc/asound/card1/pcm0p/sub0/status
```

Для рабочего выхода в нашей проверке наблюдались:

```text
access: RW_INTERLEAVED
format: S16_LE
channels: 2
rate: 48000 (48000/1)
```

При отсутствии воспроизведения файл может показывать `closed`. Это обычное состояние неиспользуемого PCM. Размеры period и buffer могут меняться между приложениями; в итоговом исправлении фиксированного переопределения этих размеров нет.

Если фактический формат не меняется, проверьте имя узла:

```sh
pw-dump > "$HOME/t100-pw-dump.json"
grep -n 'platform-bytcr_rt5640' "$HOME/t100-pw-dump.json"
```

И проверьте ошибки чтения конфигурации:

```sh
journalctl --user -b -u wireplumber --no-pager
```

### 6.4. Длительная проверка

Сначала воспроизводите файл с диска или microSD минимум 20–30 минут, затем проверьте видео и синхронизацию. После обычной перезагрузки повторите локальное воспроизведение. Для трансформера дополнительно полезна проверка после сна и открытия крышки; в этой работе устойчивость аудио после сна отдельно не подтверждена.

Записывайте источник звука, время до сбоя и характер проблемы: тишина, писк, паузы, изменение высоты или отставание. На нашем ноутбуке локальное воспроизведение превысило 50 минут, а следующая перезагрузка не вернула прежний сбой.

## 7. Если звук снова пропал

### Быстро восстановить текущий сеанс

В терминале графического пользователя:

```sh
systemctl --user restart pipewire pipewire-pulse wireplumber
```

Это кратко прервёт все аудиопотоки. При необходимости перезапустите воспроизведение в плеере. Если команда помогает, это способ восстановления, но не доказательство, что первичная причина находится исключительно в PipeWire.

### Сначала сохранить признаки сбоя

Если хотите разобраться в повторении, до перезапуска сохраните:

```sh
audio_log="$HOME/t100-audio-failure-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$audio_log"
uname -r > "$audio_log/kernel.txt"
cat /proc/asound/cards > "$audio_log/cards.txt"
wpctl status > "$audio_log/wpctl.txt"
pw-dump > "$audio_log/pw-dump.json"
journalctl --user -b -u pipewire -u pipewire-pulse -u wireplumber \
  --no-pager > "$audio_log/user-audio.log"
sudo journalctl -k -b --no-pager > "$audio_log/kernel.log"
```

Если встроенная карта по-прежнему имеет номер 1:

```sh
cat /proc/asound/card1/pcm0p/sub0/status > "$audio_log/pcm-status.txt"
cat /proc/asound/card1/pcm0p/sub0/hw_params > "$audio_log/pcm-params.txt"
```

Журналы могут содержать имена Bluetooth-устройств и другие сведения о системе. Просмотрите их перед публикацией.

### Как трактовать результат

| Наблюдение | Следующая проверка |
|---|---|
| Встроенной карты нет | Регистрация драйвера, прошивка, ошибки ядра |
| Карта есть, выбран HDMI | Выбрать встроенные динамики в настройках |
| Громкость нулевая или выход заглушен | Проверить настройки выхода и микшер |
| После перезапуска звук появился | Проверить сохранность двух рабочих конфигураций |
| Локальный файл нормален, телефон прерывается | Диагностировать Bluetooth-поток отдельно |
| Локальный файл тоже пропадает | Проверять встроенный тракт, а не только Bluetooth |
| Высота звука неверная и файл играет дольше | Измерить скорость прямого ALSA-воспроизведения |
| После обновления сломалось | Сравнить ядро, прошивку, topology и конфигурацию с копией |

## 8. Восстановление готовым sh-скриптом

Файл [restore-t100-audio.sh](restore-t100-audio.sh) **включён в этот репозиторий**. Для применения двух настроек ему не нужны другие файлы. Он не содержит фиксированного логина `lumitorus` и не требует чужой копии прошивки.

### Требования

- Linux на ASUS T100TAL; модель сверяется по DMI.
- ALT Linux, определяемый через `/etc/os-release`.
- Для установки: уже зарегистрированная SOF/RT5640-карта, PipeWire и WirePlumber **0.5.x**.
- Для установки, перезапуска и восстановления: открытый графический сеанс выбранного пользователя с работающим пользовательским systemd.
- Команды `sudo`, `getent`, `sha256sum`, `install`, `mktemp` и обычные POSIX-утилиты.

На другой модели скрипт останавливается до изменений. Это сознательное ограничение по проверенному оборудованию. Не обходите его ради похожего названия T100TA.

### Выбор пользователя

Обычный запуск выбирает текущего пользователя, запуск через sudo — `SUDO_USER`. Можно указать логин явно:

```sh
sudo sh restore-t100-audio.sh --install --user your_login
```

Замените `your_login` на владельца графического сеанса. Root без указанного обычного пользователя не поддерживается. При SSH-подключении от отдельного технического аккаунта используйте `--user` владельца рабочего стола.

### Режимы

| Команда | Действие |
|---|---|
| `sh restore-t100-audio.sh --help` | Справка; никаких изменений |
| `sh restore-t100-audio.sh --check` | Модель, карта, версии, SOF debug, сравнение файлов, состояние служб |
| `sh restore-t100-audio.sh --install` | Копия текущих двух файлов, установка рабочей конфигурации, перезапуск аудиослужб |
| `sh restore-t100-audio.sh --restart` | Только перезапуск аудиослужб |
| `sh restore-t100-audio.sh --backup` | Копия текущих двух файлов и метаданных без изменения конфигурации |
| `sudo sh restore-t100-audio.sh --restore /var/backups/t100-audio-XXXXXXXX --user your_login` | Возврат своей ранее созданной копии, включая первоначальное отсутствие файлов |

Без аргументов используется `--check`. Прежний частный скрипт имел другие режимы: опубликованный вариант **не поддерживает `--firmware`** и не заменяет прошивки.

Режим проверки информационный: код завершения 0 означает, что проверка выполнена, а не что все параметры совпали или звук исправен. Прочитайте сообщения `matches` / `missing, unreadable or different` и реально проверьте воспроизведение. Комментарии в файле могут отличаться при одинаковых действующих параметрах.

### Конфликты

Перед установкой проверяются другие modprobe-файлы с относящимися к аудио параметрами и похожие пользовательские/системные правила WirePlumber. При конфликте скрипт указывает файл и останавливается **до установки**. Проверка консервативная: правило с `audio.format` для другого устройства тоже может потребовать ручного просмотра.

Прочитайте указанный файл. Если это ваш отменённый эксперимент, сохраните его вне активного каталога и повторите установку. Скрипт не удаляет неизвестные конфигурации и не обещает обнаружить все возможные переопределения, включая параметры загрузки и нестандартные пути конфигурации.

### Резервная копия

Снимок создаётся в новом root-каталоге `/var/backups/t100-audio-XXXXXXXX`. Точный путь печатается при выполнении. Внутри — исходные `sof.conf`, `wireplumber.conf` либо отметки `.absent`, логин, модель, ядро и `SHA256SUMS`.

`--restore` возвращает **состояние из выбранной копии**, которое может быть состоянием до исправления. Чтобы сохранить именно рабочие настройки для будущего восстановления, после успешной длительной проверки выполните `--backup` и запишите путь этого снимка. Перед восстановлением скрипт также создаёт новую копию заменяемого состояния.

Скрипт не меняет GRUB, не выгружает драйверы, не устанавливает ядро и не перезагружает ноутбук автоматически. Если параметры модуля были изменены, нужна обычная перезагрузка. Перезапуск PipeWire не меняет уже загруженный `sof_debug`.

### Проверки скрипта

В репозитории есть изолированные проверки в [tests/test_script.py](tests/test_script.py). Они проверяют установку, сохранение/восстановление файлов и первоначального отсутствия, отказ при конфликте и повреждённой копии. Команды systemd и аппаратные данные подменены тестовыми: эти тесты не воспроизводят DSP и не доказывают слышимость.

```sh
sh -n restore-t100-audio.sh
python3 tests/test_script.py
```

Результат звука подтверждён владельцем конкретного ноутбука для двух приведённых настроек. Новая публичная обёртка не означает повторного испытания всех её изменяющих режимов на реальном звуковом устройстве.

## 9. Как отделить Bluetooth от встроенного звука

В ходе этой работы телефон TECNO POVA 6 успешно сопрягался, данные были доступны, аудио передавалось. При этом передача с телефона позже прерывалась, а тот же ноутбук нормально воспроизводил локальный файл с microSD более 50 минут.

Такое сравнение показывает, что проблему конкретной передачи нельзя автоматически приписать встроенной карте. Проверяйте по очереди:

1. Один и тот же или похожий файл локально на ноутбуке.
2. Передачу с телефона на тех же динамиках.
3. Близкое расположение телефона и ноутбука.
4. Отсутствие параллельных загрузок и изменение условий радиосвязи.

Состояние соединения и журналы:

```sh
bluetoothctl show
bluetoothctl devices
wpctl status
sudo journalctl -b -u bluetooth --no-pager
journalctl --user -b -u wireplumber -u pipewire --no-pager
```

Успешное сопряжение и устойчивый аудиопоток — разные проверки. По последнему сообщению владельца вопрос встроенного звука закрыт. Ранее замеченные паузы именно при передаче с TECNO не следует объявлять исправленными этой конфигурацией без отдельного длительного теста.

## 10. Прямой тест ALSA

Нужен только для повторной диагностики. Он временно отключает обычный звук приложений.

Сначала остановить проигрыватели, затем аудиослужбы и их сокеты, чтобы они не запустились автоматически при обращении клиента:

```sh
systemctl --user stop wireplumber \
  pipewire-pulse.service pipewire-pulse.socket \
  pipewire.service pipewire.socket
```

По `aplay -l` найти встроенную карту и PCM. Если это карта 1, устройство 0:

```sh
aplay -D plughw:1,0 /usr/share/sounds/alsa/Front_Left.wav
```

Команда выполняется от графического пользователя, имеющего доступ к `/dev/snd`. На обслуженном ноутбуке запуск от SSH-пользователя `codex` без перехода к владельцу сеанса давал ошибку доступа. Такая ошибка не означает исчезновение самой карты.

После теста обязательно вернуть обычные службы:

```sh
systemctl --user start pipewire.socket pipewire-pulse.socket \
  pipewire pipewire-pulse wireplumber
```

Короткий тест, который слышен после закрытия и открытия PCM, доказывает только возможность восстановить звук. Для проверки устойчивости нужен один длинный файл без переоткрытия устройства. Наш длинный ALSA-тест на прежних настройках тоже терял звук; это стало важным отличием от первоначально успешных коротких тестов.

Если возникает `Device or resource busy`, проверьте, что другие приложения и службы действительно закрыли PCM. Не переходите сразу к принудительной выгрузке модулей.

## 11. Неправильная скорость и тональность

При переходе на SST появилась отдельная проблема: видео и звук расходились, высота звука снижалась. Система заявляла 48000 Гц, но пятисекундный файл воспроизводился примерно за 6,53 секунды.

Это принципиально отличается от обычных пауз Bluetooth. Для диагностики можно создать строго пятисекундный стереофайл тишины S16LE/48000:

```sh
python3 - <<'PY'
import wave
with wave.open('/tmp/t100-five-seconds.wav', 'wb') as out:
    out.setnchannels(2)
    out.setsampwidth(2)
    out.setframerate(48000)
    out.writeframes(bytes(48000 * 5 * 2 * 2))
PY
```

После остановки PipeWire, как в разделе 10, измерить прямой вывод на правильную карту:

```sh
time aplay -q -D hw:1,0 /tmp/t100-five-seconds.wav
```

Затем снова запустить службы. Время включает небольшой запуск и завершение; не требуйте ровно `5.000` секунды. Но устойчивое превышение примерно до `6.5` секунды вместе с изменённой тональностью — существенный признак неправильной скорости.

В нашей работе гипотеза о MCLK 25 МГц не подтвердилась. Итоговое исправление использует SOF со штатным тактированием, а не компенсацию высоты в плеере.

## 12. Неудачные эксперименты

Эта таблица нужна, чтобы не повторять уже проверенные действия на том же экземпляре.

| Вариант | Что получилось | Итог |
|---|---|---|
| Перезапуск PipeWire | Временно убирал писк и тишину | Оставлен как быстрое восстановление |
| Увеличение period/headroom | Звук снова исчез примерно через две минуты | Переопределение буферов отменено |
| Только `sof_debug=1` на раннем этапе | До сбоя проходило больше времени, затем тишина | Самостоятельно не признан достаточным |
| SOF + S16LE без mmap, debug выключен | Нормальная тональность, затем тишина | Самостоятельно не признан достаточным |
| Принудительный SST | Слышен прямой ALSA, но скорость и высота неверные | Отменён |
| SST с MCLK 25 МГц | Пять секунд занимали около 6,61 секунды | Отменён |
| Другая SST-прошивка ASUS T100 | Пять секунд занимали около 6,54 секунды | Отменена |
| Итоговый SOF + debug + S16LE без mmap | Более 50 минут локального звука, повторная загрузка без проблемы | Сохранён |

Одна попытка переключить драйверы в работающем сеансе привела к kernel Oops при регистрации карты. После этого переключения выполнялись только через обычную перезагрузку.

Не используйте `rmmod -f` и не пытайтесь постоянно лечить звук принудительной перезагрузкой модулей. Не подменяйте все прошивки из случайного архива: успешная установка файла не означает правильную скорость или устойчивость DSP.

## 13. Журнал DSP для углублённой диагностики

Этот раздел можно пропустить, если звук работает. Постоянный сбор журнала не входит в процедуру исправления.

После загрузки с `sof_debug=1` на проверенной системе появился `/sys/kernel/debug/sof/trace`. Для расшифровки использовались соответствующий прошивке SOF 2.2 инструмент `sof-logger` и словарь `sof-byt.ldc` из официального [sof-bin](https://github.com/thesofproject/sof-bin).

Инструмент и словарь **не включены** в этот репозиторий. Если требуется углублённая диагностика, получите их из официального источника для своей прошивки. Проверьте архитектуру исполняемого файла и совпадение словаря. Неподходящий словарь может дать ошибку проверки или неверный вывод.

Посмотреть доступные интерфейсы:

```sh
sudo ls -l /sys/kernel/debug/sof
```

Если каталог отсутствует, сначала проверьте параметр SOF и доступность debugfs. Отсутствие каталога само по себе не означает физическую поломку динамиков.

После получения инструмента, например в `/opt/sof-tools/`, и подходящего словаря можно ограничить запись пятью минутами:

```sh
sudo timeout 300 /opt/sof-tools/sof-logger \
  -t -l /opt/sof-tools/sof-byt.ldc -o /var/tmp/t100-sof-trace.log
```

Эти пути — пример размещения **заранее установленных** инструментов. Команда не будет работать до их получения. В другом терминале проигрывайте локальный файл и отметьте время возникновения проблемы.

Завершение `timeout` по заданному лимиту ожидаемо. Во время диагностики временная systemd-служба останавливалась через 20 минут и отображала `failed / timeout`; это относилось к лимиту службы, а не к ошибке звуковой карты.

В сохранённых trace встречались предупреждения `dai_copy(): nothing to copy`, нехватка доступных байтов и потерянные сообщения. Они не установили единственную причину наших сбоев. При отправке отчёта разработчикам приложите версию ядра, прошивки, topology, тип источника и точное время сбоя.

## 14. Резервная копия и обновления

После подтверждённо успешной установки сделайте **новый снимок рабочего состояния**:

```sh
sh restore-t100-audio.sh --backup
```

Скрипт напечатает фактический путь, например `/var/backups/t100-audio-Ab12Cd34`. Подставьте именно свой путь в следующую команду:

```sh
sudo tar -C /var/backups -czf "$HOME/t100-audio-working.tar.gz" t100-audio-Ab12Cd34
sudo chown "$(id -u):$(id -g)" "$HOME/t100-audio-working.tar.gz"
```

Скопируйте архив на другой компьютер или накопитель. Скрипт также можно сохранить рядом с архивом. Копия в домашнем каталоге того же ноутбука не защищает от потери накопителя.

Восстановление архива на этом же ноутбуке:

```sh
sudo tar -xzf "$HOME/t100-audio-working.tar.gz" -C /var/backups
sudo sh restore-t100-audio.sh --restore /var/backups/t100-audio-Ab12Cd34 --user your_login
```

При существующем каталоге с таким именем сначала проверьте его содержимое и не перезаписывайте другую копию. Восстанавливайте только свой сохранённый архив. Замените имя снимка и логин на реальные.

**Содержимое копии:** два файла конфигурации либо отметки их отсутствия, модель, пользователь, версия ядра и контрольные суммы. Прошивка, topology, само ядро, микшер и полный образ ALT в публичный комплект не входят. Приватный архив, использовавшийся на ноутбуке автора, в этом репозитории не публикуется и для применения исправления не требуется.

Перед обновлением ядра или аудиостека запишите версии:

```sh
uname -r
pipewire --version
wireplumber --version
```

После обновления проверьте `sof_debug`, формат ALSA, локальное длительное воспроизведение и обычную перезагрузку. Снимок конфигурации не откатывает ядро или пакетные обновления. Если после обновления сменился формат конфигурации WirePlumber или устройство ядра, старые настройки могут уже не подходить.

Для возможного возврата прошивки сохраните её отдельно вместе с соответствующей topology, версиями и контрольными суммами. Автоматическая подмена бинарных прошивок намеренно не включена в этот скрипт: она требует отдельной проверки совместимости.

## 15. Отмена настроек

При установке `--install` скрипт напечатал путь снимка исходного состояния. Для отмены именно этих изменений используйте **тот снимок**, а не последующую копию рабочего исправления:

```sh
sudo sh restore-t100-audio.sh --restore /var/backups/t100-audio-XXXXXXXX --user your_login
sudo systemctl reboot
```

Замените путь и логин. Если до установки двух файлов не было, скрипт учитывает отметки `.absent` и убирает только эти два файла. Если они существовали, возвращает прежнее содержимое. Перед возвратом текущее состояние тоже сохраняется.

Если исправление ставилось вручную, восстановите собственные исходные файлы из копии раздела 5. Не подменяйте целиком `/etc/modprobe.d` старыми файлами: там могут быть более новые настройки других устройств.

Для ручного отключения только этой схемы, когда оба файла были созданы с нуля, можно переместить их в отдельную папку:

```sh
audio_undo="$HOME/t100-audio-disabled-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$audio_undo"
sudo mv /etc/modprobe.d/codex-t100-sof.conf "$audio_undo/"
mv "$HOME/.config/wireplumber/wireplumber.conf.d/51-codex-t100-alsa.conf" "$audio_undo/"
sudo systemctl reboot
```

Это вернёт штатное поведение загрузки и может вернуть прежний сбой. Для корректного отменения важно знать, что существовало до установки.

## 16. Краткая памятка и источники

Проверенная схема для этого T100TAL:

```text
ALT p11 + штатный SOF
    /etc/modprobe.d/codex-t100-sof.conf:
        options snd_sof sof_debug=1

    пользовательский WirePlumber 0.5:
        RT5640 → S16LE
        RT5640 → api.alsa.disable-mmap = true

    обычная перезагрузка
    длительный локальный тест
```

При повторной тишине: сохранить журналы при необходимости → перезапустить аудиослужбы → сравнить настройки с копией → восстановить комплектом → перезагрузить, если скрипт сообщил об этом.

Встроенный звук прошёл проверку владельцем. Эта инструкция не утверждает, что каждое устройство серии T100 имеет ту же проблему или что теми же настройками исправлены все случаи Bluetooth-пауз.
